## Этапы 5.12–5.18: фракции, торговцы, тренеры, квесты, предметы, ауры, группа, объекты (stage5s)

## Этап 5.11: управление как в WoW: Forever (stage5r)

Схема **Forever** (по умолчанию на New 3DS; на Old 3DS — Classic, переключается в START → Settings):

| Кнопка | Действие |
|---|---|
| Circle Pad | движение: чуть наклонить — шаг (режим ходьбы на сервере), сильнее — бег; вне боя персонаж поворачивается по стику, в бою смотрит по камере и стрейфит / пятится |
| C-Stick | камера; с зажатыми L/R — прицел (кольцо под юнитом), отпустить — выбрать цель |
| B / A / Y / X | прыжок / отмена (окно, каст, автоатака, цель) / взаимодействие (лут, NPC, тело; в бою — автоатака) / меню цели |
| D-pad | 4 ячейки панели; с ZL, ZR, ZL+ZR — ещё по 8 (D-pad + лицевые) = 28 ячеек, 3 страницы |
| R (держать) | враги: B — последний враг, A — цель цели, Y — атака, X / D-pad — следующий враг |
| L (держать) | свои: B — себя, A — цель цели, X / D-pad — следующий |
| L+R | D-pad ←/→ — страница панели, ↑/↓ — приблизить/отдалить камеру, A — камера за спину |
| START / SELECT | меню (чат, сумки, экипировка, заклинания, настройки, свободная камера, отладка, выход) / свободная камера |

- Мягкий выбор цели: заклинание или атака без живой цели берёт врага впереди (конус ±60°); взаимодействие без цели —
  ближайший труп с добычей или NPC перед лицом (на верхнем экране подсказка «[Y] Loot / Talk»).
- Привязка: START → Spells → тап по заклинанию → нажать нужную кнопку (или тап по ячейке); предметы — Bags → Bind.
  Раскладка на SD: `sdmc:/3ds/w3dproto/bars_<персонаж>.txt`, настройки — `pad.txt`. Новый персонаж получает раскладку
  из серверной панели.
- Верхний экран: две «ромашки» (D-pad и лицевые) текущего набора с кулдаунами, подсказки режимов L/R.
  Чата и боевого лога на верхнем экране больше нет — они во вкладке Chat нижнего экрана.
- Классическая схема прежняя (L цель, R атака, Y чат, A действие, X набор панели, B прыжок).
- Код: `proto3ds/source/pad.*` (схемы), `action_layout.*` (панели), `game_ui.*`; `Mover::setWalk`.
- Проверки: `proto3ds/tests/run_ui.sh` (pad_test 45 проверок + 17 сцен UI), сервер проверяет MSG_MOVE_SET_WALK/RUN_MODE
  и скорость шага (2.5 ярд/с, назад тоже).

## Камера от третьего лица

Онлайн в режиме ходьбы камера висит за персонажем на 5 ярдах вдоль направления взгляда (C-Stick — поворот и наклон),
**D-Pad вверх/вниз — приблизить/отдалить** (0–15 ярдов; ближе 0.8 — от первого лица, как раньше). Свой персонаж
рисуется моделью своей расы; камера не проходит сквозь стены (скользит вдоль них) и не уходит под землю.
Офлайн и в полёте (SELECT) — по-прежнему свободная камера.

## Этап 5.6–5.7: чат, цель, автоатака, добыча

- `net/game_spells.cpp` (заклинания, панель действий, кулдауны), `spells.txt` с именами — `src/spells.cpp` конвертера.
- `net/game_social.cpp` (часть GameSession), форматы — по vMaNGOS 1.12 (а не WoWee: там типы чата классического
  клиента взяты от WotLK — SAY=1 вместо 0, и т.д.):
  чат — SMSG_MESSAGECHAT всех видов (say/yell/party/guild/whisper/inform/emote/system/npc/channel), отправка
  CMSG_MESSAGECHAT на языке расы (Common/Orcish), команды `/s /y /p /g /w Имя /e /join Канал /1`, каналы по
  SMSG_CHANNEL_NOTIFY, «игрок не найден», SMSG_NOTIFICATION; имена отправителей вне видимости — NAME_QUERY.
  Цель — CMSG_SET_SELECTION, перебор (`pickTarget`): существа без NPC-флагов, потом NPC, игроки, мёртвые; впереди
  раньше, чем сзади. Автоатака — ATTACKSWING/ATTACKSTOP, ATTACKSTART/STOP, ошибки NOTINRANGE/BADFACING/… (на
  «не туда смотришь» персонаж сам поворачивается к цели), ATTACKERSTATEUPDATE (строки «You hit X for N», промахи,
  уклонения), LOG_XPGAIN, CANCEL_COMBAT. Добыча — CMSG_LOOT → забирается всё (деньги, предметы) → LOOT_RELEASE.
- `net/text.hpp`: UTF-8 → ASCII для консоли 3DS (кириллица транслитом, цветовые коды и ссылки WoW убираются),
  перенос строк.
- 3DS, нижний экран (`proto3ds/source/game_ui.*`) в игре: своё HP, цель (HP, расстояние, состояние), 14 строк чата
  с цветами, 5 ближайших (тап — выбрать цель), подсказка. Тап по [DBG] — прежний отладочный экран и обратно.
  Над целью — красный ромб. Клавиши в режиме ходьбы: **L** — следующая цель, **R** — автоатака вкл/выкл
  (с поворотом к цели), **Y** — чат (системная клавиатура), **A** — забрать добычу с мёртвой цели (≤ 5 ярдов).
  Существа и игроки проигрывают анимацию атаки на каждый удар (по ATTACKERSTATEUPDATE), стоя на месте.
- ПК: `w3dlogin ... --fight Имя --say "текст" ...` — выбрать живого моба по имени, подойти, бить до смерти, забрать
  добычу, писать в чат; в пакете Windows — `fight_test.bat`. `--replay` теперь печатает и строки чата/боя.

Проверено (`net/tests/run_stage5.sh`): Python-сервер (`fake_server.py --stage5 … --fight`, стороны сервера написаны
по vMaNGOS отдельно) ↔ `w3dlogin --fight`: волк в 12 ярдах (сначала «Out of range»), после двух ударов забегает за
спину (BADFACING → поворот → SET_FACING), промах, ответные укусы, смерть, ATTACKSTOP, опыт 45, добыча 23c + предмет,
release; say, whisper с ответом, канал после SMSG_CHANNEL_NOTIFY, неизвестный игрок, неизвестная команда — все 18
ожидаемых строк в журнале клиента, язык 7. Перебор целей по реальной записи: 12 юнитов, каждый по разу, порядок
групп соблюдён. 100 000 искажённых пакетов через все обработчики (ASan/UBSan). Транслит и перенос — `text_test`.
Не проверено: настоящий сервер (fight_test.bat) и консоль.

## Этап 5.5: игроки

- Конвертер `--players`: для каждой расы/пола (8×2) — модель `Character\<Раса>\<Пол>\<Раса><Пол>.m2` (CMDL,
  как у существ) и запись `CHRS`: строки CharSections (кожа, лицо, растительность на лице, волосы, бельё) и стили
  причёсок/бород (CharHairGeosets, CharacterFacialHairStyles). Слои текстуры тела — записи `CIMG`: RGBA4 в половинном
  атласе 128×128 по областям игры (лицо низ/верх, таз, торс; WoWee character_renderer). Текстуры волос — обычные TEX.
  Масштаб — из строки CreatureDisplayInfo этой модели без доп. информации. В логе строка `players:`.
- Исправлено попутно: CharacterFacialHairStyles — колонки геосетов 3/4/5 или 6/7/8 по числу полей (как WoWee);
  текстура типа 8 (skin extra) у моделей персонажей теперь берёт текстуру тела, а не остаётся белой.
- Общий код `common/w3d_character.h`: облик из полей (UNIT_FIELD_BYTES_0: раса, пол; PLAYER_BYTES: кожа, лицо,
  причёска, цвет; PLAYER_BYTES_2: борода), выбор строк CharSections по правилам WoWee (+ запасные варианты, если
  точной строки нет), выбор геосетов (теперь одно правило и для NPC в конвертере), сборка текстуры тела (альфа-
  смешивание слоёв, RGB565 в порядке тайлов PICA).
- 3DS: игрок в своём облике (displayId == nativeDisplayId) рисуется моделью расы: стример грузит CHRS, слои, модель,
  волосы, собирает текстуру тела на CPU (не больше одной за кадр, 128×128, 32 КБ VRAM на облик; одинаковые облики
  делят одну) и освобождает слои. Формы/призраки — через обычный CreatureDisplay. Свой персонаж виден в режиме
  свободной камеры (SELECT) вместо зелёного маркера. Без экипировки (бельё), оружия и шлемов пока нет.
- `w3dpreview пакет папка --player раса пол кожа лицо причёска цвет борода` — `player_..._body.png` (текстура тела,
  как на 3DS) и `player_....png` (модель в анимациях).

Проверено (`converter/tests/run_player_tests.sh`): синтетические CharSections человека (кожа 2 цветов квадрантами — видно
переворот, лицо с полупрозрачной половиной, верх лица с прозрачной половиной, борода, бельё с альфой, строка без файла)
→ 3 облика (точный, с запасными вариантами, с отсутствующей кожей): волосы, геосеты и все 16 384 текселя текстуры тела
совпадают с расчётом на Python. Стример на ПК: 6 игроков меняют облик, раса без модели уходит в CreatureDisplay,
32 сборки, ASan/UBSan/TSan, утечек нет. Реальный лог Stone Tavern: Ponuno — раса 1, пол 1 (женщина), display 50 =
native, облик 0/0/0/0/0.

## Этап 5.0c: стены (горизонтальная коллизия)

- Формат: в `W3dCollTri` поле `pad` стало `flags`: `W3D_COLL_WALL` (крутая грань, |n.z| < 0.5 — не пол, а стена),
  `W3D_COLL_M2` (из доодада, только для статистики). Старые пакеты (флаги 0) читаются как раньше — только полы.
  Сетка ячеек COLL — 32×32, у плотных тайлов (> 6000 треугольников) 64×64.
- Конвертер: коллизия WMO делится на полы и стены (`addCollisionTris`); у M2-доодадов берётся их коллизионный
  меш (bounding triangles, разобран WoWee), упрощается до `--doodad-coll-tris N` (96) без «грубого» режима
  (стены без дыр) и кладётся при каждом размещении матрицей T·Rz·Ry·Rx·S, как в рендере (доодады ADT и внутри зданий).
  Опции `--no-walls` (только полы), `--no-doodad-coll` (без доодадов), `--no-floors` (без COLL совсем).
  В логе строка `floors:` — стены/полы зданий, доодады с коллизией, размер COLL и самого большого тайла.
  `w3dpreview пакет папка --coll [X Y]` — `coll_X_Y.png`, 2 пикселя на ярд: красное — стены зданий,
  оранжевое — доодадов, синее — полы.
- Общий код (`common/w3d_collision.h`): персонаж — вертикальный цилиндр r = 0.35 ярда; стена учитывается в слое
  от ног + 0.75 до ног + 2.0 (ниже — ступени и бордюры, их берёт шаг пола 1.5; в прыжке слой поднимается — через
  забор можно перепрыгнуть). `w3d_collide_move`: стены у пути собираются один раз за ход, ход режется на шаги
  ≤ r/2 (рывок кадра не «проскакивает» тонкую стену), до 4 проходов выталкивания на шаг. Перед стеной — по её
  горизонтальной нормали (на ту сторону, откуда пришли), за настоящим концом стены — от ближайшей точки, поэтому
  вдоль стен скользишь, а углы и концы заборов обходятся плавно. Полы (`w3d_coll_query`) стены пропускают.
- 3DS: `streamerCollideMove` берёт все готовые тайлы под путём (стены у границы тайла разрезаны по тайлам).
  Вызывается в онлайн-ходьбе (на сервер уходит уже исправленная позиция, клавиша «вперёд» остаётся нажатой, как в
  оригинале) и в офлайн-ходьбе; полёт (SELECT) — сквозь всё. HUD строка 13: `walls CONTACT/clear`, мкс на кадр,
  КБ COLL в памяти, `NOMEM`, если COLL тайла не поместился в кучу (там нет ни полов, ни стен).

Проверено здесь (`converter/tests/run_wmo_tests.sh`): синтетический домик-WMO с дверным проёмом и перемычкой
(повёрнут на 25°), забор-M2 с коллизией 432 треугольника (упрощается до 96, масштаб 1.5, поворот 60°), забор поперёк
границы тайлов. 11 сценариев с ответами, посчитанными на Python отдельно (упереться в стену, скольжение под 45°,
пройти в дверь и упереться изнутри, стена рядом с проёмом, забор в лоб, перепрыгнуть забор, обойти конец, забор с обеих
сторон границы тайлов, пройти вдоль него) — ошибка ≤ 8 мм. 240 случайных прогулок (38 400 ходов, шаги 0.05–1 ярд):
независимая проверка на Python по исходной геометрии — ни одной позиции ближе r − 6 мм к стене и ни одного прохода
сквозь стену; на пакете `--no-walls` та же проверка находит 2556 нарушений (контроль, что проверка работает).
Те же 11 сценариев через настоящий стример на ПК (ASan/UBSan/TSan). Скорость на ПК: 500 стен в квадрате 10×10 ярдов
(хуже любого города) — 13 мкс на ход; на 3DS смотреть HUD.

## Этап 5.0b: полы зданий для ходьбы

- Конвертер берёт коллизионные треугольники WMO (MOPY: 0x08 коллизия, или 0x20 видимая без 0x04 детали;

## Этап 5.0: здания (WMO)

- Конвертер (`converter/src/wmo.cpp`): WMO читается парсером WoWee (корень + группы `_NNN.wmo`).
  **Каждая группа — отдельная модель MODL**, вершины относительно центра группы, поэтому на 3DS у каждой
  комнаты/секции своя плотная сфера для отсечения. Размещение группы = позиция WMO + R·центр, тот же
  порядок углов Z·Y·X, что у доодадов (WoWee placementEuler). Материалы: блендинг 0/1/2/3, двусторонность (0x4),
  без освещения (0x1); текстуры до 128 px (`--wmo-tex`), бюджет 3000 треугольников на группу (`--wmo-tris`).
- Доодады внутри зданий (набор 0 + набор из MODF) — обычные размещения M2; кватернион MODD переводится в углы
  Z·Y·X (`matrixToPlacement`, устойчиво около ±90°).
- **Дедупликация**: здание (и доодад) повторяется в каждом ADT, который задевает; теперь размещение пишет тайл,
  в котором оно стоит (или первый тайл, если хозяин вне региона). Касается и обычных доодадов — раньше на стыках
  тайлов могли быть двойные копии.
- **Обход треугольников**: при сборке любой модели подмеш разворачивается, если его обход не совпадает с нормалями
  вершин; итог — «CCW снаружи», как у земли (GPU_CULL_BACK_CCW подтверждён на консоли). В логе строка `winding:`.
- Флаг подмеша `W3D_SUBF_BUILDING` (совместим со старыми пакетами): на 3DS здания видны до дальности прорисовки
  и не пропадают при выключении доодадов (A). HUD: `bld` — видимые группы зданий.
- Опции: `--transports` (модели кораблей/цеппелинов + `transports.txt`: пути из TaxiPathNode.dbc и палубы; `--transport-filter ключи`), `--no-items` (без брони/шлемов/плеч/оружия на игроках), `--item-tris N`, `--item-tex N`, `--no-wmo`, `--no-wmo-doodads`, `--wmo-exterior-only`, `--wmo-tex N`, `--wmo-tris N`,
  `--dump-placements F` (текст: каждое размещение группы/доодада здания). `w3dpreview` рисует сверху все модели.
- Ограничения: порталов нет (внутренние группы рисуются всегда), MOCV (подсветка интерьеров) не используется,
  ходьба внутри зданий — см. 5.0b (полы).

Проверено здесь: `converter/tests/run_wmo_tests.sh` — синтетические ADT/WMO/BLP (Python), позиции и повороты групп
и доодадов против независимого расчёта (ошибка < 1 мм, < 1e-6), дедупликация, разворот обхода, индексы и обход
в пакете; разложение матриц — 200 000 случайных, включая вырожденные. `proto3ds/tests/run_streamer.sh` — стример
3DS на ПК с заглушками libctru: ASan/UBSan/TSan, выключение посреди загрузки (найдены и исправлены утечки заданий
и моделей при выключении). Windows-сборка w3dconv/w3dpreview — llvm-mingw со StormLib.

Исправлено по логу Stone Tavern: первые UPDATE_OBJECT приходят в одном TCP-чтении с LOGIN_VERIFY_WORLD и
терялись до подключения игрового слоя (в живом прогоне 0 объектов, в повторе того же лога 87). WorldClient

## Этап 3: стриминг

- Пакет может содержать регион тайлов: `w3dconv --data ... --tiles 31 47 33 49` (3×3 вокруг Элвинна).
- Тайлы подгружаются при движении: чтение с SD — отдельный поток на ядре 2 (New 3DS),
  заливка текстур — на основном потоке с бюджетом 2.5 мс/кадр, освобождение памяти — с задержкой 2 кадра.
- Ландшафт хранится в пуле одинаковых слотов (без фрагментации), модели и текстуры — с подсчётом ссылок,
  общие для соседних тайлов не грузятся повторно.
- Радиус загрузки: 1 тайл (3×3), при дальности > 450 ярдов — 2 тайла (5×5), если хватает слотов.
- Отсечение по настоящему фрустуму, небо (градиентный купол), туман (LUT по глубине), вода из MCLQ
  (полупрозрачная, текстура со сдвигом), ходьба по земле (SELECT) с билинейной высотой.
- Y — 40-секундный круг через границы тайлов (~59 ярд/с, вдвое быстрее грифона) → report.txt с вердиктом.
- Логику стриминга проверили на ПК: тот же `streamer.cpp` с заглушками libctru под AddressSanitizer и
  ThreadSanitizer, 5×5 тайлов, два круга с выходом за край региона и переключением радиуса: без ошибок,
  без утечек, камера ни разу не оказалась над незагруженным тайлом.

# Этап 2: прототип рендера (GO/NO-GO)

Цель этапа — до любых вложений в сеть и геймплей проверить, тянет ли New 3DS
один тайл ADT с доодадами в бюджете памяти: **≥25 FPS, укладываемся в RAM/VRAM,
приемлемое время загрузки с SD**.

```
common/w3d_format.h     общий формат пакета W3DP (ПК и 3DS читают одни и те же структуры)
converter/              w3dconv — оффлайн-конвертер (ПК, CMake), w3dpreview — проверка пакета
proto3ds/               w3dproto — 3DS-клиент на citro3d с замерами
proto3ds/romfs/synth.w3dp   синтетический тайл, встроен в .3dsx — запускается без игровых данных
```

## 1. Конвертер (ПК)

```sh
cd converter
cmake -S . -B build && cmake --build build -j
# синтетический тайл (без ассетов):
./build/w3dconv --synthetic -o synth.w3dp
# реальный тайл из распакованных MPQ (вывод WoWee extract_assets):
./build/w3dconv --data /path/to/Data --map Azeroth --tile 32 48 -o test.w3dp -v
./build/w3dconv --info test.w3dp            # валидатор пакета
./build/w3dpreview test.w3dp out/           # текстуры обратно в PNG + вид тайла сверху
```

Парсеры ADT/M2/BLP берутся из WoWee **без изменений** (зависят только от glm и
логгера, рендер не тянется). Опции для подбора бюджета:

| опция | что меняет |
|---|---|
| `--grid 9\|5\|3` | вершин на ребро чанка: 32768 / 8192 / 2048 треуг. на тайл |
| `--terrain-tex`, `--model-tex` | максимум размера текстуры (64 по умолчанию) |
| `--format etc1\|rgb565` | ETC1 (4 bpp; с альфой → ETC1A4) или RGB565 (с альфой → RGBA4) |
| `--max-tris N` | бюджет треугольников на модель (упрощение meshoptimizer) |
| `--max-doodads N` | ограничение числа доодадов на тайле |

## 2. Прототип (3DS)

```sh
cd proto3ds
make            # нужен devkitARM + libctru + citro3d (dkp-pacman -S 3ds-dev)
```

Пакет ищется так: `sdmc:/3ds/w3dproto/test.w3dp` → `sdmc:/3ds/w3dproto/synth.w3dp` → встроенный `romfs:/synth.w3dp`.

Управление: Circle Pad — движение (онлайн в ходьбе: влево/вправо — поворот), C-Stick/D-Pad — обзор, L/R — вниз/вверх, B — быстро,
**Y — 20-секундный бенчмарк**, X — дальность (120/250/400/800 ярдов), A — доодады вкл/выкл,
SELECT — режим отсечения граней, START — выход.

Нижний экран: FPS, время CPU и GPU на кадр, треугольники, draw calls, привязки текстур,
видимые батчи/доодады, время загрузки (SD / заливка в GPU), linear heap, VRAM, malloc-heap.
После бенчмарка в `sdmc:/3ds/w3dproto/` пишутся `report.txt` (с вердиктом GO/NO-GO) и `bench.csv`.

## 3. Порядок замеров на железе

1. Citra: убедиться, что картинка правильная (см. «Что проверить глазами»).
2. New 3DS, синтетический тайл, `Y` → report.txt.
3. Реальный тайл (Элвинн 32_48 или другой лесной) в трёх вариантах:
   `--grid 9`, `--grid 5`, `--grid 5 --max-tris 200`. Каждый — бенчмарк на 250 и 400 ярдах.
4. Смотреть не только FPS (он залочен на vsync 60/30), а **CPU ms и GPU ms**:
   16.7 мс = 60 FPS, 40 мс = 25 FPS. Это и есть запас под сеть/UI/анимации.

Критерий GO: средний FPS ≥ 25, 1% low ≥ 20, сцена < 30 МБ linear heap.

## Что проверить глазами в Citra (то, что не проверить без GPU)

- Текстуры моделей не перевёрнуты по вертикали (принято v' = 1 − v, как в tex3ds).

- Повороты доодадов: деревья стоят вертикально; на наклонённых объектах — сравнить со скриншотом из WoWee

## Упрощения прототипа (намеренно)

- Ландшафт: только внешняя сетка 9×9 на чанк, 2 слоя текстуры, вес слоя — в альфе вершины,
  освещение запечено в цвет вершины. Карта альфы 64×64 не используется (это экономит ~256 текстур на тайл).
- Модели: bind pose без скиннинга, LOD 0, одна текстура на сабмеш; заменяемые текстуры (кожа, волосы) — белые.
- Нет WMO, воды, неба, тумана, стриминга — это Этап 3. Конвертер печатает, сколько WMO пропущено.
- Отсечение — конусом по видимому направлению + дистанция (консервативно), не точный фрустум.

## Находки по WoWee (вопрос 1 из плана)

- `src/pipeline` (ADT/M2/BLP/WMO/DBC) — чистые парсеры, зависят только от glm и `core/logger`. Используются в конвертере как есть.
- `src/network` и `src/auth` (~3.4 тыс. строк) — от рендера не зависят, только логгер. Но крипто на **OpenSSL**
  (SHA1, HMAC, BIGNUM, RAND) → на 3DS заменить на mbedTLS (есть в portlibs devkitPro как `3ds-mbedtls`).
- `src/game` (~64 тыс. строк) завязан на `rendering/renderer`, `audio`, `ui/framexml`, `addons/lua` —
  целиком не переносится; на Этапе 4–5 брать оттуда разбор пакетов и состояние объектов выборочно.
