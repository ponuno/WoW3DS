# Лог производительности (этап 6)

Каждую секунду игра дописывает строку в `sdmc:/3ds/w3dproto/perf.csv` и пишет события в `perf_events.txt`.
Прошлый запуск сохраняется как `perf_prev.csv` / `perf_prev_events.txt`.
Включается и выключается в «Настройки → Интерфейс → Лог производ.» (`perflog 1|0` в `pad.txt`, по умолчанию включён).

Файлы пишет отдельный поток с низким приоритетом (ядро 2 на New 3DS). Запись на SD-карту не попадает во время кадра;
её цена видна в столбцах `log_write_ms` и `log_cost_ms`.

Разбор на ПК: `python3 tools/perflog/analyze.py perf.csv` (рядом с `perf_events.txt`). Скрипт показывает:
- где уходит кадр;
- худшие секунды и места;
- корреляции;
- память в момент минимума;
- нехватки, подгрузку, сеть, события.

`--phase all|world|loading|login|bench` выбирает, какие секунды разбирать.

## Что прислать после прогона

`perf.csv` + `perf_events.txt` (+ `report.txt`). Удобные сценарии:
1. Поле.
2. Штормград (торговый квартал, пробежка).
3. Толпа и бой с частицами.
4. Пара минут с 3D или 800x240.

Если игра упала, всё до последней секунды уже на карте.

## perf_stall.txt (с 6.6)

Сторож зависаний: если 3 с не закончился ни один кадр, сюда (и в события) пишется `STALL: no frame for N s; main thread at "<метка>"
(last finished phase: <фаза>); sound thread running / NOT running; linear free …, VRAM free …`, повтор раз в 10 с, затем `STALL over`.
Метка — где основной поток: `C3D_FrameBegin (waiting for the GPU)` = GPU не закончил прошлый кадр; `prepare: …`, `draw: …`, `texture uploads`,
`streamerUpdate` … = наш код на основном потоке. Сторож работает и при выключенном логе.
С 6.7, если кадр ждёт GPU дольше 1 с, метка — состояние очереди GX: `C3D_FrameBegin: GPU queue stuck … - N commands, S sent, D done,
waiting on <command list / memory fill / display transfer / texture copy>`; через 2,5 с «готово» имитируется один раз (событие).

## perf_events.txt

- **Шапка**: консоль, лимит ядра 1, размеры кучи, linear-памяти и VRAM на старте.
- **phase / map / online / settings**: смены режима (login, loading, portal, world, offline, bench), карты, настроек.
- **hitch N ms**: кадр дольше 50 мс (до 4 в секунду) с разбивкой по фазам кадра (≥ 1 мс), проходам отрисовки (`r.*`),
  стадиям стримера и числу вызовов отрисовки.
- **LINEAR MEMORY LOW / HEAP LOW / VRAM**: память опустилась ниже порога (4/2/1 МБ linear, 1 МБ кучи, блок VRAM < 256 КБ).
  В строке указано, кто её держит.
- **OUT OF MEMORY**: не удалось выделить память (буфер текстуры, модель, существо, вода, загрузка текстуры, коллизия).
  Пишутся размер запроса и свободная linear-память. Пометка `FRAGMENTED` значит: свободно много, но цельного блока нужного размера нет.
- **map N: pack … waited**: сколько длилась смена карты или телепорт.
- **session summary** (в конце):
  - FPS и перцентили кадра, всего и «в мире»;
  - худшая секунда и где она была;
  - средняя разбивка кадра;
  - минимумы памяти и нехватки за сессию;
  - итог по SD-карте.

## perf.csv — столбцы

Единицы: мс, КБ. Слово «за секунду» значит разницу с прошлой строкой. `avg` — среднее по кадрам секунды, `max` — худший кадр.

### Где и что
| столбец | смысл |
|---|---|
| `t_s`, `t_win_ms` | секунды с запуска лога; длина окна строки |
| `phase` | `login` / `loading` / `portal` / `world` / `offline` / `bench` |
| `map`, `tile_x`, `tile_y`, `x y z`, `yaw` | карта, тайл, позиция персонажа (или камеры) |
| `move` | `walk` / `floor` (на здании) / `swim` / `fly` / `taxi` / `ship` |
| `online` | в мире на сервере |

### Кадры
| столбец | смысл |
|---|---|
| `f_frames`, `f_fps` | кадров за секунду |
| `f_ms_avg/min/p50/p90/max` | длительность итерации главного цикла |
| `f_over33/50/100`, `f_hitches` | кадров длиннее 33 / 50 / 100 мс |
| `f_worst_phase` | самая дорогая фаза худшего кадра |
| `f_cpu_avg/max` | кадр без ожидания (`ph_wait`): работа CPU основного потока |
| `f_wait_avg/max` | ожидание в `C3D_FrameBegin` (кадровая синхронизация и окончание работы GPU) |
| `f_gpu_avg/max` | время GPU на прошлый кадр (`C3D_GetDrawingTime`) |
| `f_c3dcpu_avg/max` | citro3d: от `FrameBegin` до `FrameEnd` |
| `f_cmdbuf_max` | заполнение буфера команд GPU (2 МБ), %. 100% = падение |
| `f_bound` | `vsync` (57+ FPS), `gpu` (GPU дольше CPU), `cpu` |
| `f_kicks`, `f_kick_lead`, `f_gpu_span`, `f_kick_ms` | с 6.3: ранние пинки GPU за кадр; насколько раньше `FrameEnd` GPU начал (`f_gpu_*` считают от `FrameEnd`); полное время GPU ≈ `f_gpu_avg + f_kick_lead`; цена пинков на CPU |

### Фазы кадра: `ph_<фаза>` — среднее, `phx_<фаза>` — максимум за секунду (мс)
| фаза | что внутри |
|---|---|
| `input` | опрос кнопок |
| `net` | экраны входа и сеть: здесь разбираются все пакеты сервера |
| `ui` | логика нижнего экрана, схема управления, музыка зоны, проверка смены карты |
| `move` | камера, движение, коллизия, плавание, корабли |
| `spells` | эффекты заклинаний (SpellView) |
| `sound` | звуки мира и голоса |
| `game` | `GameSession::update`, отбор юнитов, модели существ, маркеры |
| `hud` / `touch` | сборка списков верхнего HUD / нижнего экрана |
| `glue` | 3D-сцена экранов входа |
| `stream` | `streamerUpdate` (подробности — `st_*`) |
| `prepare` | с 6.4: проход видимости (`collect`) до ожидания GPU — идёт, пока GPU рисует прошлый кадр |
| `wait` | ожидание GPU прошлого кадра (и VSync: с 6.4 только если включён или кадр короче 15,5 мс) |
| `portrait` | портреты в рамках |
| `world` | `rendererDraw`, построение команд GPU (подробности — `r_*`) |
| `huddraw` / `touchdraw` | отрисовка интерфейса верхнего / нижнего экрана |
| `flush` | `C3D_FrameEnd`, `uiEndFrame`, отложенные освобождения |
| `mapload` | блокирующие ожидания смены карты / телепорта |
| `other` | счётчики report.txt, отладочная страница, сам лог |

### Память (КБ)
Сумма по владельцам сверяется с занятым. Разница идёт в `*_other`. Если `*_other` растёт, утекает что-то неучтённое.

| столбец | смысл |
|---|---|
| `lin_total/free/used` | linear-куча |
| `lin_pool`, `lin_pool_used` | пул земли (выделен целиком при старте) |
| `lin_water`, `lin_buildings`, `lin_doodads`, `lin_unit_models`, `lin_models_loading`, `lin_creatures` | геометрия |
| `lin_tex`, `lin_tex_<класс>`, `lin_tex_bodies` | текстуры в linear |
| `lin_staging`, `lin_staging_retry` | данные текстур, ещё не загруженные в GPU |
| `lin_coll`, `lin_sound`, `lin_ui`, `lin_cmdbuf`, `lin_other` | коллизия, звук (эффекты + потоки + кэш), интерфейс (страницы + вершины + шрифт), буфер команд, остальное |
| `vram_free`, `vram_largest` | свободно и наибольший цельный блок. Блок меньше размера текстуры — она уйдёт в linear |
| `vram_tex`, `vram_tex_<класс>`, `vram_tex_bodies`, `vram_targets`, `vram_reserve`, `vram_portraits`, `vram_other` | VRAM по владельцам |
| `heap_size/used/free`, `heap_arena`, `heap_arena_free`, `heap_top` | обычная куча (24 МБ) по `mallinfo` |
| `heap_heights`, `heap_instances`, `heap_coll`, `heap_liquid`, `heap_charimg`, `heap_index`, `heap_other` | куча по владельцам |
| `app_used`, `app_free` | регион APPLICATION системы |
