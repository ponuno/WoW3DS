# ARM11 compile check without devkitARM

Used by the assistant's sandbox (pkg.devkitpro.org is blocked there) to compile the 3DS
sources for armv6k/mpcore hard-float against the real libctru/citro3d/devkitPro-newlib headers.
It catches compile errors and missing declarations; it does not link or run anything.

## Variant A — system clang (stage 5; used when PyPI/zig is not reachable)

    git clone https://github.com/devkitPro/libctru; git clone https://github.com/devkitPro/citro3d
    git clone --filter=blob:none --sparse -b devkitPro https://github.com/devkitPro/newlib
      (sparse-checkout: newlib/libc/include newlib/libc/machine/arm newlib/libc/sys/arm)
    git clone --filter=blob:none --sparse --depth 1 -b llvmorg-18.1.3 https://github.com/llvm/llvm-project llvm
      (sparse-checkout: libcxx/include libcxxabi/include libcxx/vendor)
    git clone https://github.com/devkitPro/picasso   # g++ -DPACKAGE_STRING='"picasso"' source/*.cpp -o picasso
    DEPS=<dir with the clones> tools/armcheck/armcheck.sh proto3ds/source/*.cpp net/*.cpp

`cfg/` holds a hand-written libc++ 18 `__config_site` (no threads/filesystem/localization) and
`__assertion_handler` (copied from libcxx/vendor/llvm/default_assertion_handler.in).
Since stage5r the script defines `__INT32_TYPE__` as `long int` like arm-none-eabi-gcc (devkitARM's `int32_t` is
`long`, clang's default is `int`): `std::max(0, int32_t)` compiled here but failed in devkitARM.
Clang 18 needs no `-target` tarball: `--target=arm-none-eabihf -mcpu=mpcore -mfloat-abi=hard`.

## Variant B — zig (stages 2–4)

    pip install ziglang
    export ZIGLIB=$(python3 -c "import ziglang,os;print(os.path.dirname(ziglang.__file__))")/lib
    export NEWLIB=... LIBCTRU=... CITRO3D=... W3D=<this repo>
    python3 -m ziglang c++ $(eval echo $(cat flags.txt)) -std=gnu++20 -fno-rtti -fno-exceptions -O2 -c file.cpp

Both variants: `stub/` holds newlib.h/_newlib_version.h (normally generated by the newlib build);
`terrain_shbin.h` / `model_shbin.h` stand in for the headers the Makefile generates from the shaders.

## Windows tools (w3dconv.exe / w3dpreview.exe, stage5s)

CMake with the llvm-mingw toolchain and local clones for FetchContent (glm 1.0.1, meshoptimizer v0.22, rg-etc1,
WoWee, StormLib):

    cmake -S converter -B build-win -DCMAKE_TOOLCHAIN_FILE=mingw.cmake -DCMAKE_BUILD_TYPE=Release \
        -DFETCHCONTENT_SOURCE_DIR_GLM=... -DFETCHCONTENT_SOURCE_DIR_MESHOPTIMIZER=... -DFETCHCONTENT_SOURCE_DIR_RGETC1=... \
        -DFETCHCONTENT_SOURCE_DIR_WOWEE=... -DFETCHCONTENT_SOURCE_DIR_STORMLIB=...
    make -C build-win w3dconv w3dpreview

mingw.cmake: CMAKE_SYSTEM_NAME Windows, CMAKE_CXX_COMPILER .../bin/x86_64-w64-mingw32-clang++ (C, RC likewise),
CMAKE_FIND_ROOT_PATH .../x86_64-w64-mingw32.
